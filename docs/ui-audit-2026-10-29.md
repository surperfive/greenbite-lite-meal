## 2. 对账口径（新增脚本）

```bash
node scripts/audit-spec.mjs      # 源码层：字号/色值/间距/描边/img
node scripts/audit-ui.mjs        # 运行时：对比度/命中区/溢出/语义
```

`audit-spec.mjs` 的判定是**白名单式**：不在 `docs/ui-spec.md` 登记过的值就报。

## 3. 需要你拍板的三件事

### 3.1 间距里的「1~3px 微调值」要不要归整？

现状 32 处，集中在这几个：

| 值 | 次数 | 典型用途 |
|---|---|---|
| `py-[3px]` | 12 | 小胶囊内部垂直居中微调 |
| `py-[5px]` / `px-[5px]` | 8 | 同上 |
| `p-[1.5px]` / `py-[1.5px]` | 4 | 给 ring / border 做内衬 |
| `mt-[3px]` / `gap-[3px]` | 4 | 图标与文字基线对齐 |
| `py-[7px]` / `py-[2.5px]` / `mt-[42px]` | 3 | 单点补丁 |

规范写的是「4 的倍数（4/6/8/10/12/14/16/20/24）」。这 32 处**全部违反**。

- **归整**（3→4、5→6、7→8）：每个元素会高出 2px，12 个胶囊累计会让若干行变高，
  已经调好的对齐要重排，**视觉会变**。
- **不归整**：在规范里开一个「1~3px 光学微调档」，只允许用于垂直居中/基线补偿，不得用于布局间距。

我倾向后者（写进规范并注明用途），因为这些都是 1~2px 的光学对齐，不是布局节奏。

### 3.2 抽卡页那 8 个艺术字要不要并入字号阶？

`GachaPage` 46px、`GachaBurstReveal` 16/18px、`StickerModal` 34/46px。
它们是抽卡结果 / 贴纸卡上的展示字，不是正文层级，规范 1.4 已把插画排除在统一之外，
但**字号**这一条没写豁免。

建议：在 §2.1 加一行「展示型数字 16~46 只允许出现在抽卡/贴纸卡，且同一屏不超过两处」。
否则下次有人照着抄到业务页就乱了。

## 4. 一个必须说明的误报（脚本本身的问题）

第一版 `audit-spec.mjs` 报「27 张图缺 alt」，实际是 **0 张**。

原因：用 `/<img[\s\S]*?>/` 抓标签，`DishImage` 的 `<img ref={(node) => {` 里那个 `=>`
被当成了标签结束符，正好把后面的 `alt={alt}` 切掉。改成扫描 `{...}` 深度 + 跳过引号后才准。

**教训**：这类脚本的每个数字都要能对上一个具体文件行，否则不要写进报告。
现在脚本对每条结果都带 `file:line` + 标签片段。
