> 这份文档是**全站唯一的视觉/交互口径**。新增页面、改组件、接新素材前先看这里，
> 不再各自拍脑袋定字号和颜色。
>
> 落地校验：`node scripts/audit-ui.mjs`（逐页量对比度 / 命中区 / 语义 / 溢出），
> 报告：`outputs/spec-report.html`。
>
> **v2（2026-10-30）**：用 `ui-ux-pro-max` 的 App UI 交付清单对 v1 做了一次缺口体检，
> 补上 v1 完全没覆盖的三类问题 —— **安全区**（§7.1）、**减弱动效**（§5.1）、
> **状态徽章的诚实性**（§5.2），并把「返回键」记为已知缺口（§9）。

---

## 0. 一句话原则

**视觉可以小，但不能读不出；可以密，但不能点不中。**
小字号和高密度是这个产品的风格（菜品卡要看得到价格、热量、标签），
所以规范不要求把字放大，只要求：**每一个字都过 4.5:1，每一个按钮都点得准。**

---

## 0.1 规范的边界：什么能压、什么不能压

体检工具（`ui-ux-pro-max` 的 119 条 UX 规则 + App 交付清单）是**查漏的**，不是**改品牌的**。
落进本项目的规则必须过这一道筛：

| 类别 | 处理方式 |
|---|---|
| **结构类**：安全区、命中区、焦点可见、语义标签、减弱动效、返回行为 | ✅ 一律采纳并落地。这些不改变观感，只改变"能不能用"。 |
| **比例类**：间距档、圆角档、字号阶、描边粗细 | ✅ 采纳，但档位按本项目的既有体系（§2/§3）定，**不照搬工具的 4/8dp 默认值**。 |
| **配色类**：主色 / 强调色 / 语义色 | ⛔ **一律不采纳**。工具给「餐饮外卖」推的是西式餐厅的红金配色（`#DC2626` + 深金），与本项目青柠 `#C7F665` + 玫红 `#FC5294` 的品牌资产冲突。工具的配色只用来做**对照检查**（比如"你的主色在白底上够不够"）。 |
| **字体类**：字体族 | ⛔ 不采纳。工具给的是 `Playfair Display SC` + `Karla`（西式餐厅调性），项目是 `Plus Jakarta Sans` + `Noto Sans SC`（中文小程序）。 |

一句话：**工具能给的是「有没有漏」，不是「该长什么样」。**
同类取舍的既有判例见 §1.2（玫红对比度）与 §3.3（区块头裸排版）—— 都是"以观感定版，
把代价写清楚"，而不是让规范反过来推翻定版。

## 3. 间距与圆角

- **4 的倍数**：4 / 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24。禁止 7、9、13、18 这类随手值。
- 区块纵向节奏：卡片内 `10~14`，卡片之间 `12`，大区块之间 `20~24`。
- 圆角：按**容器体量**取档，同一容器只用一档。2026-10-29 对账时把实际在用的 18 个值收成 6 档：

  | 档 | 区间 | 用在 | 全站实例 |
  |---|---|---|---|
  | 角标 | 4~7 | 贴图角标、内嵌小块 | 4 / 5 / 6 / 7 |
  | 小元件 | 9~10 | 标签、图标底、小胶囊 | 9 / 10 |
  | 中块 | 14~16 | 信息条、内嵌卡、列表行 | 14 / 15 / 16 |
  | 卡片 | 17~20 | 商品卡、券包行 | 17 / 17.5 / 18 / 19 / 20 |
  | 大卡 | 22~24 | 大卡片、抽屉、头图容器 | 22 / 24 |
  | 容器 | 26~28 / `full` | 弹窗、大面板、胶囊 | 26 / 28 / full |

  - 新增代码**优先取区间端点**（10 / 14 / 18 / 22 / 26），区间内只在“和相邻元素对齐”时使用。
  - ⛔ 不要再出现 11 / 12 / 13 / 21 / 23 / 25 这类值 —— 它们和相邻档只差 1px，
    改一个就会让整排卡片看起来“圆角不一样大”。
  - ⛔ 同一个容器不要出现两种圆角语言（比如外 20、内 14 却又不加内边距）。

### 3.1 描边

| 类型 | 写法 | 用在哪 |
|---|---|---|
| 中性分割 | `1.5px #070906/12` | 券包行、分段器、表单块 |
| 深墨强调 | `1.5px #070906` | Gacha 勾选框、黑色按钮 |
| 白色外环 | `2px #FFFFFF`（`ring-2 ring-white`） | **我的页积分量表**（黑胶囊条）、头像外圈 —— 让深色块从青柠底上"浮"起来 |
| ~~品牌玫红~~ | ~~`2px #FC5294`~~ | **已撤销**（2026-10-29 加过 1.5px → 2px，同日「不要这个描边了」全撤） |

- 中性 / 深墨档统一 **1.5px**；白色外环 **2px**。
- 白色外环为什么用 `ring` 不用 `border`：目标元素尺寸是**算出来的**（积分条 10px 外高、
  `p-[2px]` 出 6px 内条），`border` 会挤内容盒、把内条压成 4px；`ring` 走 box-shadow，
  零布局影响。白环会向外占 2px 视觉间距，别再靠 `gap` 去补。
- ⛔ **卡片外框不要用玫红描边**：首页人气卡在 10-28（图区绿 inset）、10-29（整卡玫红 border）
  两次加过描边都被撤。卡片与 `#F4F6F8` 页底的分离只靠投影（`0 4px 16px rgba(0,0,0,0.06)`），
  要加强分割就调投影或底色，别再动 border。
- 不加 `hover`/`active` 描边色变化（跳档会读成两个品牌色）。
- 卡片有 `overflow-hidden` 时，描边走**整卡 `border`**（border-box，外宽不变），
  不要再往图区塞 `shadow-[inset_...]` —— 那圈绿内描边 2026-10-28 加过又被要求去掉。

### 3.2 文字白描边（贴纸字）

深色小字压在青柠渐变上时，用 **8 向 `text-shadow`** 堆白边，让字像贴纸浮起来：

```jsx
style={{ textShadow: '1px 0 0 #fff, -1px 0 0 #fff, 0 1px 0 #fff, 0 -1px 0 #fff, 1px 1px 0 #fff, -1px -1px 0 #fff, 1px -1px 0 #fff, -1px 1px 0 #fff' }}
```

- 用在：**我的页积分数字**（`680/1000`，9px）。
- ❗ 不用 `-webkit-text-stroke`：它是**居中**描边，会把 9px 字的笔画两边各吃掉一半，
  字直接变细变花。`text-shadow` 只向外堆，字形本体不动。
- 白边宽度上限 = 字号 ÷ 9（9px → 1px）：再粗会连成一坨。字号上到 11px 以上可加到 1.5px。
- 配白边的字**必须实黑**（`text-black`）：半透明黑（`black/55`）叠在青柠底上本来就发灰，
  再加白边会从笔画里漏出来、整块发脏。次要信息最多 `black/65`。

### 3.3 区块头（Section Header）

全站区块头只有一个标准形（2026-10-29 定稿，第二版）。首页两条都是它：

```
[黑圆 24px + 图标 14px] [标题 15/800 纯黑]  …………  [入口文案 12/700 灰字 + ›]
```

已落地：
| 位置 | 图标 | 标题 | 右侧 |
|---|---|---|---|
| 首页 · 限时超值福利 | 黑圆 `#070906` + 玫红火焰 `#FC5294` | 限时超值福利 | 查看更多 › |
| 首页 · 人气当季轻食 | 黑圆 `#070906` + 玫红火花 `#FC5294` | 人气当季轻食 | 全部菜单 › |

- **裸排版**：不加容器。没有白胶囊底、没有投影、没有边框，直接排在页面底色上；
  层级靠「字号差 + 左右留白」拉开，不靠盒子。上下间距交给父级 `space-y-3`（12px），
  ⛔ 不要自己用 `h-[40px]` 之类撑高度。
- 左侧黑圆 24px 是这一行最重的锚点，⛔ 不要缩回 18px（15px 标题会把它压小、整行变碎）。
  圆底一律 `bg-black #070906`（⛔ 不用 `slate-900`，偏蓝，两条并排能看出来）。
  圆内图标 14px，可以是火花也可以是火焰，但**颜色一律品牌玫红 `#FC5294`**：
  2026-10-29 11:41 用户「这两个图标的黄色和绿色都改成小程序的红色」，把金火焰 `#FDCF29`
  与青柠火花 `#C7F665` 一起换掉了 —— ⛔ 别再单独染回黄/绿。玫红在黑底上 6.77:1，清晰。
- 右侧入口是**灰字文字链**（`slate-600` 12px/700 + 14px chevron，`stroke-[2.2]`），
  挂 `gb-hit-y` 把命中区撑到 44 高；视觉上仍是一行字，⛔ 不要做成实心按钮。
- **⛔ 不加英文副标**（`POPULAR PICKS` / `LIMITED TIME` 都已删）：区块头只留中文标题，
  英文副标那种「排版装饰」留给真正的 hero 层。要恢复必须全站一起恢复。
- 标题塞不下时截断标题（`truncate`），**不要压缩右侧入口**。

### 3.4 分类栏 tab（点餐页左栏）

宽 116px 的竖栏，每个 tab `min-h-[56px]`，一行排「24px 图标 + 文字 + 可选上标」：

```
[图标 24]  [分类名 12/800 截断] ᴴᴼᵀ
```

- 文字 **12px**（⛔ 不用 12.5：不在字号阶上，且 5 字分类会被挤）。
- 「全部热卖」那颗 **HOT 上标**：8px / 900 / 全大写 / `tracking-tight` / `#FC5294`，
  与分类名同一行、`items-start` + `-mt-px`，读作标题右上角的上标。
  ⛔ 不要放回标题下方单独一行（2026-10-29 12:15 用户「HOT 改成热卖右上角」改上来的）。
- **宽度算术（必须守住）**：116 − pl10 − pr4 − 图标24 − gap4 = 74px 可用；
  「全部热卖」12px ≈ 47px，HOT 8px ≈ 17px，gap 4px → 右缘距青柠块边还剩 ~5px。
  想加大 HOT 字号/字距，必须同步缩标题或 `gap`，否则 HOT 会压到 `rounded-r-2xl` 圆角上。
- 未选中态：图标 `slate-400`、文字 `slate-500/600`；选中态整行转黑（`text-black`），
  底色是青柠块 + 左侧 6px 黑条，不要另加边框。

## 4. 触摸目标

### 4.1 三档标准

| 档 | 尺寸 | 适用 |
|---|---|---|
| **A 主操作** | ≥ 44×44 | 底部 Tab、主按钮、加购、结算 |
| **B 常规** | ≥ 24×24 且四周留 8px | 列表行、筛选胶囊、次要按钮（WCAG 2.2 AA 底线） |
| **C 图标按钮** | 视觉可 22~28，**命中区必须 44** | 收藏、加减、详情、信息入口 |

### 4.2 怎么把命中区撑大而不改版式

```html
<button class="gb-hit">     <!-- 四向撑到 44×44 -->
<button class="gb-hit-y">   <!-- 只撑高度到 44，横排紧邻时用这个 -->
```

原理：`::after` 绝对定位撑出透明命中区，**不参与布局、不改视觉**。
⚠️ 横排紧挨的按钮（数量加减器）只能用 `gb-hit-y`，否则相邻命中区互相抢点击。
⚠️⚠️ **`gb-hit` 不要和 `absolute` 混用**。该类的 `position: relative` 写在 `:where()` 里
   （特异性 0），定位类才会赢；早先没包 `:where()` 时它会把元素自己的 `absolute` 顶掉，
   元素掉回文档流、再被 `right-*` 左移，直接压到旁边的内容上（首页人气卡的加号压住价格）。
   图标按钮要**贴边**就交给布局（flex 两端对齐），不要用绝对定位。
⚠️ 整行文字链（查看更多 / 全部菜单 / 查看全部 / 切换门店）不要用伪元素 ——
   它会向上吃掉相邻行（比如搜索框底边）的点击。改用**加内边距 + 抵消外边距**：

```html
<button class="py-1 -my-1">        <!-- 高 16 → 24，排版高度不变 -->
<button class="px-1.5 -mx-1.5 py-1.5 -my-1.5">  <!-- 双向扩，四周仍不越界 -->
```

### 4.3 已知例外

- **轮播指示点**（6×6，右上角）：三个点总宽 40px，撑到 44 会互相覆盖。
  保留 6×6，理由是它**有等价操作**（左右滑动 + 自动轮播），且不属于唯一入口。
  这是规范里唯一登记在案的例外。

### 4.4 相邻目标的间距 ≥ 8px

命中区可以靠伪元素撑大，但**撑大的前提是四周有余量**。两个可点元素之间
视觉间距小于 8px 时，扩出来的命中区会重叠，手指落在缝里会命中"先渲染的那个"
—— 表现为"点左边却触发了右边"。

| 场景 | 下限 | 现状态 |
|---|---|---|
| 数量加减器（`gb-hit-y` 横排紧邻） | 视觉间距 ≥ 8px，只扩高度不扩宽度 | ✅ 24×24 视觉、24×44 命中 |
| 筛选胶囊（点餐页热量档、订单页状态档） | 间距 8px，高度 ≥ 24px | ✅ 高 24.7 / 间距 8~10 |
| 底部导航 5 个 tab | 五等分，互不重叠 | ✅ ≈73px/个 |
| 轮播指示点 | **例外**（见 §4.3） | 6×6，间距 3px |

- ⛔ 不要再出现 `gap-0` / `gap-1`（0/4px）把两个可点元素贴在一起。
  确实要贴（比如分段控件的两段），就在外层做**一个**可点区域、内部切分状态，
  而不是两个按钮各自撑命中区。
- 审计算法：`audit-ui.mjs` 输出的 `hitW/hitH` 只反映单元素，**间距要人眼核对**。
  量法：两个相邻按钮的 `getBoundingClientRect()` 边缘差 < 8 即违规。

## 5. 状态与反馈

- 所有可点元素必须有按下反馈（`active:scale-95` 或换色），**80~150ms** 内可见。
- 反馈不能改变布局边界（用 transform / opacity，不要改 padding / 高度）。
- 禁用态：降饱和 + `cursor-not-allowed` + 文案保持可读（≥4.5:1），不能靠"变灰到看不见"表达。
- 加载：切页有品牌过场（`LoadingScreen`），异步动作给 toast，不留"点了没反应"。

### 5.1 减弱动效（reduced motion）—— 双轨，缺一不可

这个产品是重动效的：开屏光斑、抽卡爆闪、菜品飞向购物车的抛物线、详情页 spring 缩放。
对前庭功能敏感的用户，这类**大幅位移**会引起眩晕。系统级开关必须被尊重。

两条路互不覆盖，**都要在**：

| 轨道 | 负责什么 | 实现 | 位置 |
|---|---|---|---|
| **JS 动画**（motion / framer） | `motion.div` 的 `animate` / `whileHover` / `layout` | `<MotionConfig reducedMotion="user">` 挂在 `App` 根节点 | `src/App.tsx` |
| **CSS keyframes** | 加载屏光斑、海浪、抽卡 `@keyframes` | `@media (prefers-reduced-motion: reduce) { animation: none }` | `src/index.css` / 组件内联 `<style>` |

- 挂根节点而不是逐组件传：新加的 `motion.*` 自动继承，不会漏。⛔ 不要再各处手写
  `useReducedMotion()` 判断 —— 那是 v1 的做法，只覆盖了开屏那一处，其余全漏。
- `reducedMotion="user"` 的语义是**跳过 transform / layout 的过渡，但仍落到最终值**。
  实测（390×844，点开菜品详情 120ms 取样）：

  | 媒体状态 | 详情层 transform | 高度 | 下层缩放 |
  |---|---|---|---|
  | `no-preference` | `matrix(0.9105, …, 25.56)` 弹簧中 | 768 | 0.9747 过渡中 |
  | `reduce` | **`none`** | **844** | 0.93 直接就位 |

  即：不再有缩放+位移动画，画面直接到位。这是 motion 的既定语义，不是 bug。
- ⛔ 不要把 `reducedMotion` 写成 `"always"`：那会让所有设备的动效一律失效，品牌感全丢。
- 新增 CSS 动画时，必须同步往 `@media` 块里加选择器；否则它在 reduce 下照旧播放。

### 5.2 状态徽章必须诚实

底部导航「订单」上的红色计数徽章是**状态指示**，不是品牌装饰。

- 数值必须等于**真实进行中订单数**（`delivering / cooking / pending`）。
- 为 0 时**不渲染**（`badge: n > 0 ? n : undefined`），⛔ 不要回落成 `1`。
  2026-10-30 修的就是这一处：原写法 `n > 0 ? n : 1` 让订单全部完成后红点仍然亮着，
  用户点进去是空的 —— 违反「状态不能撒谎」，也让红点从"提示"退化成"贴纸"。
- 实现：`BottomNavBar.tsx` 的 `tabs` 数组里 `badge` 字段，渲染侧用 `badge !== undefined` 判空。
  调用方 `App.tsx` 只负责算数，不再兜底。
- 同理适用于任何计数/角标：`FloatingCart` 的购物车数量、收藏页的 `favsCount`。
  ⛔ 0 不要显示成 0，直接不显示。

## 6. 可访问性

- **焦点必须可见**：`:focus-visible` 统一 2px `#070906` + 2px 外扩（`index.css` 已全局设置）。
  唯一例外是抽卡页两枚召唤大按钮（用户明确要求去焦点圈，靠整块可点+按压反馈兜底）。
- 图标按钮必须有 `aria-label` / `title`；纯装饰图标加 `aria-hidden="true"`。
- 图片必须有 `alt`（纯装饰用 `alt=""`）。
- 图片必须显式声明加载时机（2026-10-29 对账前 27 张图全部没写，浏览器只能按默认急加载）：
  - 首屏关键图：`loading="eager" fetchPriority="high"` —— 首页轮播、点餐页头图、我的页头图/头像/订单卡。
  - 其余全部：`loading="lazy" decoding="async"`。
  - 判据不是「在第几屏」，而是**「用户不滚动就能看到吗」**。拿不准就 lazy（视口内的图浏览器会立即加载，不会延迟）。
- 不能只靠颜色传达信息（售尽、缺货要同时有文案）。
- 模态弹窗：`createPortal` 挂 `body`，遮罩 `bg-black/62` + `backdrop-blur-sm`，ESC / 点遮罩可关。

## 7. 布局

- 内容宽度跟随手机壳（390），**不写死 px 容器宽**；列表用 `flex-1 min-h-0 overflow-y-auto`。
- 底部固定条（Tab、悬浮购物车）必须给滚动内容留出底部 inset（`pb-28` 起步），
  不能让最后一张卡被切一半。
- 禁止横向溢出（`scrollWidth > clientWidth` 视为 bug）。

### 7.0 内容轨道（content rail）—— 390 壳统一左右 12

**所有页面的内容左右缘一律是 `12 / 378`**（390 − 12），由区块容器的 `px-3` 决定。

2026-11-02 对账：五个页面原本各用一套边距，切 tab 时内容边缘会跳 2~6px：

| 页面 | 改前 | 改后 |
|---|---|---|
| 点餐 | `px-3`（12） | 12 ✅ 基准 |
| 首页 | `px-2.5`（10） | **12** |
| 订单 | `px-3.5`（14） | **12** |
| 我的 | `px-3.5`（14） | **12** |
| 十鲜盲盒 | `px-4`（16） | **16（保留例外）** |

- ⛔ 新增区块容器一律 `px-3`，不要再出现 10 / 14 / 16。
- **唯一例外是十鲜盲盒**：它是整页插画布局，白色食材卡是「浮在青柠底上的浮层」，
  四周 16 的呼吸感是设计的一部分，改成 12 会让左右窄上下宽的失衡。
- ⚠️ **不要用负外边距去扩大点击区**。`px-1.5 -mx-1.5` 这种写法会让视觉右缘跑到 378 之外
  （点餐页「切换」实测 384，比搜索框右缘多出 6px）。只扩单侧：`pl-1.5 -ml-1.5`
  —— 左缘由 `-ml` 抵消、右缘不外扩，命中区宽度不变。
- 装饰性出血（`absolute -right-1` 的插画、抽卡机 `L-1.9/R391.9`）**不算违规**，
  它们是刻意让图形压边，不参与轨道对账。

### 7.0.1 文字列（text column）—— 胶囊的盒子对齐 ≠ 文字对齐

**盒子在 12，文字不一定在 12；用户看到的是文字。**

上一版只对账了盒子（卡片、搜索框都在 12），但每颗胶囊都有内边距，文字被推进去多少完全取决于
内边距写了几。2026-11-02 逐字实测（`getBoundingClientRect` 的墨迹盒，不是元素盒），点餐页
顶部三行的文字左缘分别是 **23 / 27 / 30** —— 三行叠在一起看是斜的。

| 行 | 首元素 | 内边距链 | 改前墨迹 | 改后墨迹 |
|---|---|---|---|---|
| ① 外卖 / 自提 | 灰色轨道 + 白滑块 | `px-3` + 容器 `p-0.5` + 边框 1 | 27 | **25**（`px-2.5`） |
| ② 门店名 | 14px 地图针 + 间距 | `gap-1`（4） | 30 | **28**（`gap-0.5`） |
| ③ 筛选胶囊 | 胶囊 | `px-2.5` + 边框 1 | 23 | **25**（`px-3`） |

三行离散度从 7px 收到 3px。② 收不到 25 —— 它前面压着一个 14px 图标，硬压会把图标挤没，
3px 是这一行能给到的极限。

**规则**

1. **同一视觉带（同一段纵向区域）里，行首文字的墨迹左缘必须落在同一条列上，允许 ±3px。**
   差 4px 以上就是 bug，不是「差不多」。
2. **胶囊做行首时，调胶囊而不是调文字**：改 `px` 让墨迹落到列上，不要用负外边距把盒子拖出轨道。
   点餐页筛选行就是这么做的：四颗胶囊 `px-2.5 → px-3` 各 +4，容器的 `gap` 从 6 降到 4
   抵消一部分，行尾 363 → 371，仍在 378 内。
3. **图标开头的行不参与同列**，图标的视觉边就是它的边；只要求「同类行之间」一致。
4. **卡片内部自成一条列**（卡内容边 + 卡内边距），不和页面轨道比。
   但**卡片内部不允许两种对齐方式并存** —— 十鲜盲盒食材卡原来菜名居中、卡路里左对齐，
   三张卡的菜名左缘是 51.1 / 171.6 / 280.4，网格看起来是散的。改成 `text-left pl-1` 后
   菜名和 `kcal` 同在「卡内容边 + 4」，三张卡一致。

**怎么验**：不要目测。用 Range 量墨迹盒（`rg.selectNodeContents(el)` 取 `getBoundingClientRect`），
元素盒会带上 padding，量出来是假的。批量脚本见 `scripts/_align3.mjs`（临时件，用完删）。

### 7.0.2 胶囊：一行放不下时改哪一头

ui-ux-pro-max 的 `Compact Label Overflow`（High）：**紧凑标签在一行内保持完整，不允许折行，
也不允许只靠 hover 提示补全**。点餐页菜品卡的「折 + 标签 + 销量」正好踩这条。

这一行只有 118px。原来 折徽章(38) + 间距(4) + 5 字标签(61) + 间距(4) + 销量(26) = **133**，
溢出 15px，`overflow-hidden` 把「9300+」裁成「930」。墨迹右缘实测 378.9 —— 正好顶在卡片边上。

修的顺序（**先压间距，再压内边距，最后才动文案**）：

1. 行间距 `gap-1 → gap-0.5`（−4）
2. 折徽章 `px-1.5 → px-1`（−4）
3. `DishTag` 的 `px-2 → px-1.5`（−4，全局，首页人气卡同步变紧 2px）
4. 「高膳食纤维」→「高纤维」（−18，5 字降 3 字，语义不变）

改后最长一行 112px，留 6px 余量；五张卡的销量右缘全部落在 367，离散度 0。

⛔ **不要用 `truncate` 兜底**。试过 `min-w-0 truncate`，flex 直接把「月售1.2万+」压成「月…」，
比裁掉一半更糟 —— 这是把溢出换成了信息丢失。

### 7.1 安全区（safe area）

本项目是 390 宽手机壳，桌面预览里 `env(safe-area-inset-*)` **一律求值为 0**，
所以"有没有做安全区"在浏览器里看不出来 —— 只有真机（iPhone home indicator、
全面屏安卓手势条、刘海）才暴露。这是 v1 最大的盲区。

| 位置 | 用法 | 文件 |
|---|---|---|
| 底部导航 | `.safe-pb-tight`（`max(8px, env(safe-area-inset-bottom))`） | `BottomNavBar.tsx` / `index.css` |
| 悬浮购物车 | `bottom-[calc(92px+env(safe-area-inset-bottom,0px))]` | `FloatingCart.tsx` |
| 加载屏头部跳过按钮 | `top: max(18px, env(safe-area-inset-top))` | `index.css` |
| 通用 16px 档 | `.safe-pb` / `.safe-pt` | `index.css` |

- ⛔ **不要直接写 `env()` 裸值**（`padding-bottom: env(safe-area-inset-bottom)`）：
  桌面求值为 0，会把本该有的 8px 内边距吃掉，导航凭空矮一截。
  一律用 `max(现有值, env(...))` 包住，**桌面观感与改动前逐像素一致**，只有真机多出那段。
- ⛔ 不要用 `.safe-pb`（16px 档）替换导航的 `pb-2`（8px 档）—— 那会把导航撑高 8px，
  等于改了版式。档位不同，别混用。
- 悬浮购物车的 `92px` 是"导航高 + 间距"的实测值。导航一旦因安全区长高，
  购物车必须同步 `calc` 上移，否则真机上会被导航压住一半。
  ⛔ 不要把 92 改大来"预留"安全区 —— 桌面会凭空空出一块。
- 验证方法（真机不可得时的替代）：DevTools 里临时给 `body` 加
  `padding-bottom: 34px` 无效，正确做法是改 `env()` 的模拟值需要设备仿真；
  或者直接量 `getComputedStyle(nav).paddingBottom`，在桌面应恒为 `8px`。

## 7.2 壳的宽高自适应（不是"响应式"）

**结论先行：本项目不做桌面重排，只做三件事 —— 宽度 360~430 不塌、高度贴合视口、不横向溢出。**

小程序没有"响应式"这个命题：微信的适配模型是 `rpx`（屏宽恒等 750rpx 等比缩放）+ 默认锁竖屏，
视口宽度永远在 320~430 之间（±13%）。所以这里要的是**自适应**，不是断点重排。
（同理：桌面三栏、平板分栏、横屏重排，三样对小程序用户都没有场景，一律不做。）

### 7.2.1 宽度：上限 410，下限 360

`DeviceFrameWrapper` 的壳是 `w-full max-w-[410px]`：≤410 跟随视口，>410 封顶居中。
**壳内部没有一条布局断点**（全项目 `sm:` / `md:` 共 9 处，6 处在壳上，2 处是 `GachaPage`
的 `md:max-w-2xl`（壳只有 410，`max-w-xl`=576 永不触发），1 处是注释）。

**下限 360 是通过窄屏降级保住的**（`max-[374px]`，Tailwind 4 任意变体）：

| 元素 | 390（设计宽） | <375 | 为什么 |
|---|---|---|---|
| 左侧分类栏 | 116px | **104px** | 少 12px，图标 24 + 间距 4 后标签还剩 62px，"全部热卖" 4 字 = 48px 放得下 |
| 菜品卡内边距 / 间隙 | `p-2.5` / `gap-2.5` | **`p-2` / `gap-2`** | 再省 6px |
| 菜品卡文字列 | **118px** | **106px**（原 88） | 菜名从「牛…」回到能读 4~5 字，加号不再压价格 |

⛔ **不要动缩略图尺寸**。`DishCoverArt` 的 `size` 是 JS 参数（内嵌字号、内边距都按它算），
角标又是相对父容器绝对定位的 —— 用 `transform: scale()` 缩放只缩插画、不缩角标，会错位；
用 `fluid` 模式则字号不跟着变。要缩必须连角标一起改，代价远大于省下的 14px。
320/330 一代（iPhone SE 一代、老安卓）已放弃，只要不横向溢出即可。

### 7.2.2 高度：三段式

| 视口 | `.shell-h-safe` | `.shell-maxh-safe` |
|---|---|---|
| < 640px | `100dvh`（回退 `100vh`） | `max-height: 100dvh` |
| ≥ 640px | `min(844px, calc(100dvh − 32px))` | `min(844px, calc(100dvh − 32px))` |

- ≥640 之所以要减 32：壳外面有 `sm:my-4`（上下各 16px）。壳高 = 100dvh 时，
  壳 + 边距 = 视口 + 32px → **整页永远多出 32px 纵向滚动**，手机壳底边被切在首屏外。
  ⚠️ 16 + 16 必须与 `sm:my-4` 同步，改边距不改 CSS，白边立刻回来。
- 之所以封 844：不封的话 1440 高的显示器会把壳拉成 1440，手机比例就没了。

### 7.2.3 两个曾经"写了但没生效"的坑

1. **类名拼错**：tsx 写 `max-shell-h-safe`，`index.css` 定义的是 `.shell-maxh-safe`。
   `fitHeight`（盲盒页）的 max-height 兜底**从来没生效过** → 壳被内容撑到 803/868，
   底栏掉到首屏外（360×640、412×732 实测都要滚才能切 tab）。现已统一为 `shell-maxh-safe`。
2. **`sm:h-[844px]` 是死代码**：Tailwind 4 把 utilities 放进 `@layer`，
   而未分层的 `.shell-h-safe` 永远压过它。桌面壳高实际一直是 100dvh。
   已删除，改由 §7.2.2 的 media query 统一给值。⛔ 别再加回来。

### 7.2.4 `fitHeight` 页面必须自带滚动层

盲盒页内容高度**随宽度变**（头图 `aspect-[4/3]`、卡片栅格）：390×844 时 836 刚好塞下，
360×640 是 803、412×732 是 868。壳被 `.shell-maxh-safe` 锁在视口内之后，
里面没有 `flex-1 min-h-0 overflow-y-auto` 的话，超出部分会被壳的 `overflow-hidden` 直接切掉。

现在的写法（`App.tsx` 的 gacha 分支）是 `w-full flex-1 min-h-0 overflow-y-auto`：
内容放得下就不滚（视觉零变化），放不下只滚这一层，**底栏留在原位**。

⛔ 不要把滚动放在壳或 `body` 上 —— 那样底栏会跟着一起滚走，等于退回修复前的状态。
⚠️ 副作用：小屏上这一层会"能滚但看不出能滚"（同 §9.4 的图鉴弹窗案例）。
只要卡片被拦腰截断，用户就能读出"还能往下",当前接受这个代价。

### 7.4 图片资源：按显示尺寸定像素，按人眼阈值定质量

**尺寸**：一律做到「显示尺寸 × 2」为止 —— 再高就是白白多传字节（浏览器会自己缩），
再低就会被放大、肉眼可见发虚。实测各图 `object-fit` 后再算，`cover` 和 `contain` 算法不同：

| object-fit | 缩放依据 | 能不能裁 |
|---|---|---|
| `contain` / `fill` | `min(2×宽, 2×高)` 等比缩 | 不能，整图都在画面里 |
| `cover` | `max(2×宽, 2×高)`，两维都得够 | 超出部分是永远看不见的，技术上可裁（本轮未裁，留给壳宽变化） |

**质量**：不是拍一个统一值，而是对每张图从低质量往上试，取**刚好达到画质阈值**的那档。
阈值按最终显示尺寸分档 —— 越小越狠，这也是用户要的「越小的可以压得越狠」：

| 目标宽度 | PSNR 下限 | 说明 |
|---|---|---|
| ≤ 90px | 32.5 dB | 图标/食材片，看的是轮廓和色块 |
| ≤ 200px | 34 dB | 小徽章、四宫格入口 |
| ≤ 420px | 35 dB | 菜品图、cutout |
| > 420px | 35.5 dB | 大图（banner、背景） |

PSNR 参照的是「原图缩到同一尺寸」，所以量到的是**编码损失**，不含降采样本身。

**两条硬护栏**：压完不比原图小就保留原图（PNG 调色板偶尔会变大，实测 4 张）；
没有显示尺寸数据的历史图按同类保守值处理，不瞎压。

**结果（2026-11-04）**：`public/` 位图 1877 KB → 1167 KB，**-37.9%**。分档效果符合预期：

| 目录 | 个数 | 前后 | 幅度 |
|---|---|---|---|
| `ingredients/`（显示 37px） | 10 | 44.8 → 17.5 KB | **-61%** |
| `welfare-icons/`（58px） | 3 | 19.5 → 7.6 KB | **-61%** |
| `assets/aistudio/`（159px） | 3 | 112.5 → 41.3 KB | **-63%** |
| `entry-norm/`（94~100px） | 4 | 43.3 → 26.9 KB | -38% |
| `dishes/`（85~194px） | 24 | 885.2 → 480.3 KB | -46% |
| `backdrops/`（398px） | 4 | 207.3 → 145.2 KB | -30% |
| 根目录（banner 410px） | 12 | 564.4 → 447.8 KB | -21% |

⛔ 大图（`hero-poster-*`）只降到 -8~-23% 是**正常的**：它们本来就是 80~85 质量导出的，
在同等 PSNR 下没有多少余量，硬压只会出现块噪。

**复跑**：`node scripts/measure-image-usage.mjs`（重新量显示尺寸 + object-fit，写 `outputs/img-scan/fit.txt`）
→ `node scripts/compress-images.mjs`（出报表到 `outputs/img-scan/compress-report.txt`）
→ 确认后加 `--apply`。原图备份在 `.backup/images-20261104/`，回滚直接把该目录覆盖回 `public/`。
`sharp` 装在 `.tools/`（不写进 `package.json`，否则会被 npm prune 清掉 —— 踩过）。

**还能再小的路**：转 WebP 可到 **-42~-45%**（同 PSNR 下比 JPEG 小 15% 左右），
但要改约 60 处引用路径 + 重建 `dist`，属于格式迁移而不是压缩，本轮没做。

## 9. 已知缺口（记录在案，尚未落地）

### 9.1 返回键 / 历史栈 —— ⚠️ 唯一的功能级缺口

**现状**：全站导航是单一 `activeTab` state（`App.tsx`），没有 `pushState` / `popstate`。
后果：详情页、门店页、任意 tab 深一层时，**安卓物理返回键和浏览器后退会直接退出整个应用**，
而不是退回上一层。小程序里表现为"直接关掉"，H5 里表现为"退回上一个网站"。

**为什么没顺手改**：这不是样式问题，是**导航契约**。加 `history` 会改变每个 tab 切换是否入栈、
多层弹窗的返回顺序（详情页开在门店页之上时先退哪个），改错了会出现"要按两下才动"
或"退过头回到首页"，比现在更难用。需要先定清楚：

| 待定 | 选项 |
|---|---|
| tab 切换是否入栈 | A. 入栈（返回能回上一个 tab）· B. 只替换（返回直接退出） |
| 遮罩层（详情 / 门店 / 弹窗） | 必须入栈，返回等于关闭 |
| 首屏兜底 | 栈底时返回 = 退出（不拦截） |

**落地方案（定稿后一次做完）**：`history.pushState({ tab, overlay }, '', '#tab')` +
`window.addEventListener('popstate', …)` 还原状态，遮罩层优先于 tab 还原。
在定稿前 ⛔ 不要零散地给某一两个页面加返回处理 —— 半套历史栈比没有更危险。

### 9.2 图标尺寸没有 token

现在图标尺寸散落在 `14 / 16 / 20 / 22 / 24 / 28`（底部导航 20、区块头 14、
分类栏 24、卡片入口 22~28）。视觉上靠肉眼对齐，没有统一档。

- 目标档位（与 §2 字号阶同构）：**14 / 20 / 24 / 28** 四档。
- 现状**可用**，暂不强制归并 —— 改图标尺寸会牵动卡片排版，收益低于风险。
  新增代码请往这四档上靠，⛔ 不要再引入 18 / 26 这类中间值。
- 同一视觉层内描边粗细必须一致（`stroke-[1.8]` 与 `stroke-[2.4]` 不能并排出现在同级图标上）。

### 9.3 审计里可忽略的噪声（已登记豁免）

`audit-spec.mjs` 会稳定报出下列几类，**都是登记过的豁免，不用逐条修**：

| 报告项 | 实际 | 处理 |

| `[R1] 字号 < 9px` ×3 | 抽卡页 / 爆闪动画的展示型数字 | §2.1 已豁免（图形的一部分） |
